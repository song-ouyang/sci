## Variants

- **original_train**: Tuned models trained only on the original revision-v3 training features (TEP late snapshots of 100 training runs; FD001 windows of 100 training engines) and scored on exactly the numeric features rendered in the LLM prompts. Like-for-like reference; hyperparameters by grouped CV.
- **legacy_untuned**: Exact reproduction of the earlier untuned references (RF 300 trees, seed 20260926; StandardScaler + RBF SVM C=1, gamma=scale) on the original training features. Continuity check only.
- **tep_phase_aware**: FAIR-TRANSFER (extra training information): original TEP late training rows plus the sample-40 snapshot (same definition as the early test panel) of the SAME 100 training runs for all 7 classes, i.e. labelled examples of the early phase. Run-disjoint from every test panel.
- **fd002_in_domain_raw**: FAIR-TRANSFER (extra training information): labelled FD002 training engines (official train_FD002, disjoint partition from the 60 test engines). Same 60-feature 30-cycle summary as the LLM, no regime normalization. Balanced sampled cut points (see training_design).
- **fd002_in_domain_regime_norm**: FAIR-TRANSFER (extra training information + different features): as fd002_in_domain_raw, but every sensor is z-scored per operating regime (KMeans, 6 regimes, fitted on train_FD002 settings) before computing the same 30-cycle summaries. Test features are transformed the same way, so they are NOT the numbers the LLM saw.
- **fd001_regime_norm_transfer**: FAIR-TRANSFER (unlabelled target statistics + different features): classifier trained only on FD001 labels (FD001 z-scored with its own training statistics, one regime). FD002 test engines are normalized with per-regime statistics estimated from UNLABELLED train_FD002 sensor data (no RUL used). Also scored on the FD001 panel (same normalization) as an in-domain check.

FD002 training design: Balanced labelled windows from train_FD002 run-to-failure trajectories. For every training engine and every RUL class, FD002_CUTS_PER_CLASS observation endpoints are drawn without replacement (fixed seed) among those with a complete 30-cycle past window whose RUL (= failure cycle - endpoint cycle) falls into the class. Bins match the test panel: Healthy RUL>80, Degrading 30<RUL<=80, Critical RUL<=30. The FD002 test panel is balanced (20/20/20), so classes are balanced by construction.

- TEP: 100 training run IDs vs 140 test run IDs; overlap 0. Early training snapshots come only from training runs; 2240 frozen TEP rows re-extracted from raw RData matched exactly.
- FD002: 260 train_FD002 engines vs 60 test_FD002 engines; raw-row overlap of test windows with training partition: {'fd002_test_windows_in_train_FD002': 0, 'fd001_test_windows_in_train_FD001': 0}. Test features/labels recomputed from raw files.
- No test feature vector is identical to any training row in any variant. Panel IDs equal the LLM case-file IDs.
- Legacy RF/SVM reproduce the stored earlier results exactly on all five panels.

## Caveats

- Exact CV ties (reported as `tied best`) are broken by grid order, which lists defaults first.
- Reported predictions use one fixed seed. RF and MLP accuracy move by a few cases across seeds (see the seed sensitivity section); with n=60-70, differences of 1-3 cases between methods are within this noise.
- Fair-transfer variants are upper-bound style references, not equal-information comparisons with the LLM. tep_phase_aware is trained at exactly the test sample index (40); a deployed model would not know the time since fault onset. Regime-normalized variants also use features the LLM never sees.
- FD002 in-domain training cut points are sampled uniformly within each RUL bin; the test panel's RUL distribution within bins follows the official truncation (training ranges: {'Healthy': [81, 311], 'Degrading': [31, 80], 'Critical': [0, 30]}).
- The FD001 original panel is reconstructed exactly from the frozen revision-v3 datasets.json (same IDs, features, labels); no approximation was needed.
