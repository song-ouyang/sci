# Offline collapse-only control: result-informed plan

Recorded on 30 September 2026 before computing this new control. The original aggregate results and per-call failures have already been inspected; this is a post hoc analysis, not a preregistered or independent experiment. Existing frozen responses and protocols remain unchanged.

Use all 27 planned requests from `canary_hydraulic_v1`, grouped into the nine original arm-by-block windows of exactly three calls. Preserve each call's integer position in the frozen schedule, not lexical sorting of derived order values. Include all calls, all three arms and every window; do not select subgroups by performance.

The fixed primary collapse-only rule rejects a valid request if at least 90% of all 27 returned labels are the same (25 or more). It reads no reference label, focal-role indicator, known class balance or model confidence. It uses the already returned labels for all serialized records, including the records that served as canaries, so this tests the incremental value of knowing those labels at fixed payload; it does not estimate performance after removing canary records from prompts. Pre-fixed sensitivity thresholds are 85%, 95% and 100%, all reported without choosing a winner.

Compare Single (first scheduled call), Known-answer (first valid call with at least 8 of 9 canaries correct), Collapse-only (first valid call passing the fixed modal-share rule) and Vote over the same maximum three requests per window. Primary Vote resolves an all-label tie by the first call, as in the original frozen canary protocol; also report a clearly separate abstention-on-tie variant. No passing call means all 18 focal decisions in the window are withheld. Invalid/missing first calls yield no Single labels; voting requires all three valid calls; an invalid/missing request cannot pass either gate. All planned windows retain their denominators.

Report accepted correct/error counts, rejected decision counts, accepted-case error, coverage, correct yield, request counts, available input-plus-output tokens and summed client duration for each policy; resources belong to the calls that policy would require, not to a free cache. Request counts and service seconds are not monetary or end-to-end latency estimates. Report per-call Known-answer × Collapse-only acceptance cross-tabs, errors passed uniquely by each gate, and per-window/per-case decisions so retained errors are auditable. The ordinary collapse gate cannot repair a wrong output; first-passing selection can choose a later, better or worse label.

No p-value or population confidence interval is added. Shared requests, three temporal blocks and reuse of the same 18 focal cycles preclude treating 162 window decisions or 486 focal outputs as independent sources. No within-output panel resampling will be sold as a fresh trial. A separately prepared new-source/time-period study, if authorized and run, will be reported separately regardless of its result.
